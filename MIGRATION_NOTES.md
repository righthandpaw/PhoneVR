# PhoneVR: ALVR v20 -> v21 migration notes

Last updated: 2026-10-05

## Status

The Android client (the `main` flavor, built on `alvr_client_core`) now connects to an ALVR v21
streamer, decodes video on the phone's hardware decoder (H.264 and HEVC verified) and renders it
through the Cardboard distortion renderer. Head orientation comes from the Cardboard head tracker
(3DoF). Position is not tracked yet.

- **ALVR version:** v21 is not a tagged release. It is the `master` branch of `alvr-org/ALVR`
  (the main repo's newest tag is still v20.14.1). This port was built against commit `9f118394`
  (`21.0.0-dev14`). The client library header from `dc84d683` (also `21.0.0-dev14`) is identical.
- **Test device:** an Android phone with an Adreno 619 GPU, OpenGL ES 3.2, with
  `GL_OES_EGL_image_external` supported.
- **Build host:** Ubuntu in VirtualBox, JDK 17, Rust 1.97.1, Android NDK 25.2.9519653.

## 1. Build configuration changes

No source folders were removed in this branch. `app/src/gvr/`, `app/src/androidTestGvr/` and
`code/mobile/mobile-common/` are still present. They belong to the legacy custom-protocol client
and should no longer be built, because the build files below were changed to produce only the
ALVR-based variant. They can be deleted in a later cleanup.

The build files were changed to produce a single ALVR-based variant (from the original port notes):

- `app/build.gradle`: the `gvr` / `noGvr` product flavor split and the Google VR SDK dependency
  and unzip step were removed.
- `app/CMakeLists.txt`: the `src/gvr` subdirectory and the include directories only the legacy
  custom protocol needed (`asio`, `eigen`, `ifaddrs`) were removed.
- `prepare-alvr-deps.sh`: the GVR SDK download and the `nogvr` flag were removed.
- `alvr_main.cpp`: foveated-encoding settings are no longer parsed from the settings JSON, because
  v21 delivers them on the `StreamingStarted` event. The `nlohmann/json` dependency is gone from
  this file.

Consequence: this branch no longer builds the legacy `gvr` flavor that talks to the old PhoneVR
PC server, so it is not suitable to send upstream as it is.

## 2. `alvr_client_core.h`

The header used by this project was compared with the header generated by
`cargo xtask build-client-lib` (cbindgen) from a clean ALVR checkout at `dc84d683`. There were no
differences. The Gradle `buildClientLib` task regenerates this file on every build.

## 3. `alvr_main.cpp` API changes (v20 -> v21)

| Area | v20 | v21 |
|---|---|---|
| View params | Part of `alvr_send_tracking`'s arguments, recomputed every tick | Sent separately via `alvr_send_view_params()` (head-local pose), when eye offsets or FOV change |
| Head prediction offset | `alvr_get_head_prediction_offset_ns()` | Removed from the C API. A fixed estimate (`ESTIMATED_PREDICTION_OFFSET_NS`) is used instead. Consider upstreaming a C export for `ClientCoreContext::get_total_prediction_offset()`. |
| `alvr_resume_opengl` | 5 arguments (trailing `always_direct` bool) | 4 arguments |
| `alvr_render_lobby_opengl` | `AlvrViewInput[2]` | `AlvrLobbyViewParams[2]` (adds `swapchain_index`) plus a `render_background` bool |
| `alvr_render_stream_opengl` | `(buffer, swapchain_indices[2])` | `(buffer, AlvrStreamViewParams[2], foveation_center_shifts)`. Needs a per-eye `reprojection_rotation` and `fov`, computed with the new `alvr_rotation_delta()` helper. |
| `alvr_get_frame` | Returned view params, buffer and timestamp | Returns timestamp and buffer only. View params and foveation centers come from `alvr_report_compositor_start(timestamp, &metadata)`, which can return `false`; the caller then reuses the last good metadata. |
| Foveation parameters | Parsed by hand from `alvr_get_settings_json()` | Delivered on the `StreamingStarted` event |
| `AlvrStreamConfig` | No upscaling fields | New `enable_upscaling` / `upscaling_*` fields (left disabled) |
| Decoder | Created implicitly | Must be created by the client when `ALVR_EVENT_DECODER_CONFIG` arrives (see section 4) |

## 4. Problems found while getting video working

### 4.1 Host textures were invisible to the Rust GL context

- **Symptom:** the lobby never rendered correctly. Rust logged `texture 2 is NULL` and
  `framebuffer is not complete`. When streaming started, the app aborted (`SIGABRT`) inside
  `StreamRenderer::new`, in `check_error`, on a leftover GL error `0x506`.
- **Cause:** `alvr_initialize_opengl()` calls `GraphicsContext::new_gl()`, which builds its own
  wgpu GL instance. Its EGL context was created without a share context, so the swapchain
  textures that PhoneVR creates in its own context did not exist there.
- **Fix:** a small patch to `wgpu-hal` 25.0.2 (`src/gles/egl.rs`) passes the thread's current EGL
  context as the share context to the three `create_context` calls. It relies on PhoneVR calling
  `alvr_initialize_opengl()` while its own context is current (it does, in `surfaceCreatedNative`).
  The patch is in `code/mobile/android/PhoneVR/patches/wgpu-hal-25.0.2-share-egl-context.patch`.
  It also contains some `ALVR GLES` debug log lines that can be dropped; the essential change is
  replacing `None` with `share_context` in the `create_context` calls.
- **Related workaround:** the `alvr_*_opengl()` calls make Rust's context current and leave the
  thread with none, so `alvr_main.cpp` restores the app's EGL state afterwards (`EglStateGuard`).

### 4.2 The decoder was never created

- **Symptom:** the lobby froze after connecting, no video frames arrived, and the stream renderer
  never drew a frame, while SteamVR still received poses.
- **Cause:** the client did not handle `ALVR_EVENT_DECODER_CONFIG`.
- **Fix:** on that event, read the config bytes with `alvr_get_decoder_config` (call once with
  `nullptr` for the size, then again to fill a buffer), fill an `AlvrDecoderConfig` using the codec
  from the event, and call `alvr_create_decoder`. Ignore later decoder-config events until
  reconnection, as the header says. Call `alvr_destroy_decoder` on `STREAMING_STOPPED`.

### 4.3 Hardware decoder rejected the first input without MediaCodec options

- **Symptom:** the Qualcomm decoder (`c2.qti.avc.decoder`) logged `Unsupported input buffer`
  on the first input, ALVR retried, then restarted the connection with `Too many decoder errors`.
  The software decoder worked.
- **Fix:** pass the same options the stock client gets from the server defaults in
  `AlvrDecoderConfig.options`: `operating-rate` = `INT32_MAX`, `priority` = 0 and
  `vendor.qti-ext-dec-low-latency.enable` = 1 (all int32). With these, hardware decoding works for
  H.264 and HEVC. The generic `low-latency` key is deliberately not set; ALVR's own settings code
  notes it crashes some Android phones.

## 5. Setting up the ALVR side

1. Check out ALVR at the commit above and build as usual (`prepare-alvr-deps.sh`, which runs
   `cargo xtask build-client-lib`). `JAVA_HOME`, `ANDROID_HOME` and `ANDROID_NDK_HOME` must be set,
   and an Android SDK platform and build-tools must be installed.
2. Download the `wgpu-hal` 25.0.2 crate (`https://static.crates.io/crates/wgpu-hal/wgpu-hal-25.0.2.crate`),
   unpack it, and apply the patch from inside the unpacked folder:
   `patch -p1 < <path to>/wgpu-hal-25.0.2-share-egl-context.patch`
3. In ALVR's top-level `Cargo.toml`, add:
   ```toml
   [patch.crates-io]
   wgpu-hal = { path = "<path to the patched wgpu-hal-25.0.2 folder>" }
   ```
   The path used during development was absolute and specific to one machine; use your own.

## 6. Known issues and not done yet

- **ARCore and drift correction:** not integrated on this branch. `getPose()` in `alvr_main.cpp`
  is the extension point; it currently returns Cardboard's gyro-only orientation with position
  fixed at the origin.
- **Stuttering:** present in v20 as well. A fix exists on the author's separate v20 ARCore branch
  and has not been merged here. Weak Wi-Fi also contributed in testing.
- **Stale decoder-config event:** a `DECODER_CONFIG` event arrives after each `STREAMING_STOPPED`,
  and the handler creates a decoder while no stream is active. Harmless so far, but it should be
  tidied.
- **Patch path:** the `wgpu-hal` patch is referenced by an absolute path on the development
  machine, which must be replaced before others can build this.
- **CI:** `.github/workflows/build.yml` and `release.yml` still reference the removed
  `gvr` / `noGvr` Gradle tasks and will need simplifying before CI can pass.
- **Likely obsolete:** `driver/PVRServer` and `code/windows` (the PC side of the legacy
  protocol). Left untouched.
